**Implementation audit — 20 September 2026**

The core Steps 1–8 implementation exists and its fixture acceptance tests pass. It does not yet satisfy the broader goal of reliably editing the application's own generated drawings and arbitrary real projects end to end. The largest gaps are the connection between generated components and the index, saved-file verification, failure recovery, and legacy workflows that bypass the new protections.

This was a review, not a repair. No application code, real drawing, or production database was intentionally changed. Existing uncommitted work was preserved. Findings below distinguish executed reproductions from source-level findings and unverified deployment requirements.

**Evidence and scope**

- Reviewed the roadmap, previous architecture analysis, project storage/extraction/scanning/editing/orchestration paths, API integration and chat UI, and legacy sketch/P&ID/CAD3D/vessel and batch-workflow connections. The legacy subsystem analysis was cross-checked against current source; it was not accepted wholesale as current fact.
- Windows, Python 3.11.9. Ran `.\venv\Scripts\python.exe -m pytest tests/ -q`: **956 passed, 10 skipped, 0 failed, 29 warnings**, 103.59 seconds. Warnings are ezdxf/pyparsing deprecations. Live AI tests remain opt-in. This does not verify real AutoCAD writes.
- `python -m pip check`: no broken requirements.
- Actually executed the RTree virtual-table creation: it succeeded. **RTree is available in this environment**; the suite also exercises the cKDTree path and the missing-extension error handling.
- Additional reproductions used isolated temporary SQLite databases and DXFs, mocked AI/COM or filesystem faults. They are separate audit probes, not new passing tests added to the suite.
- Read all **82 available DXFs** outside the virtual environments successfully. Their layout entities were LINE (4,457), CIRCLE (476), TEXT (4,862), LWPOLYLINE (608), ELLIPSE (286), DIMENSION (666). No proxy layout entities or class names containing PLANT/PNP/AECC/CIVIL were found. There are also 36 DWGs; their native object semantics were not verified.
- The existing application `jobs.db`, inspected read-only, contains `jobs` and `sqlite_sequence`, with no registered-project tables yet. The new schema is created lazily by storage access, so this is evidence that the project workflow has not initialized this database, not proof that the schema implementation is missing.
- `ODA_FILE_CONVERTER` is not configured in either this process environment or the local `.env`. No live LLM or AutoCAD editing was invoked during this audit.

**Bugs and integration gaps, in priority order**

1. **High — Generated P&ID pipes cannot use the advertised indexed resize workflow. Reproduced.** `PipeRunComponent(tag="P-101", label="P-101", points=[[0,0],[1000,0]])` renders a POLYLINE plus TEXT. The persisted DXF contains LWPOLYLINE and TEXT, both with `tag=None`; querying P-101 returns zero matches. The extractor recognizes selected block attributes and `TAG=` XData, but the generator/executors do not preserve component tags that way. Even after manually attaching the expected XData, planning fails with `Length resize requires a LINE`. The ten-drawing acceptance fixture specifically uses a tagged LINE, so it misses this integration failure. Preserve component identity during generation, map legacy drawings explicitly, and support the actual pipe representation before treating existing generated pipes as editable components. Sources: [pipe renderer](../src/framework/pid/components/piping.py), [polyline commands](../src/framework/pid/symbols.py), [tag extraction](../src/cad/extractor/dxf_extractor.py), [planner type restriction](../src/cad/orchestrator.py).

2. **High — Saved property changes can be falsely reported as validated. Reproduced with a save fault.** With a COM-shaped document whose `Save()` returned without persisting, requesting entity color 3 produced a pending ChangeSet with `passed=1`, while fresh extraction still returned color 256. The executor compares re-extracted values only for RESIZE_COMPONENT. Other operations merely require extraction to succeed; the manager then records a generic success. Compare the saved entity/layer/document values for each operation, including secondary entities moved during resizing. Document SummaryInfo persistence is also not established by the fixture adapter, whose summary properties live only in a SimpleNamespace. Sources: [executor](../src/framework/commands/modification_executor.py), lines 242–261; [validation recording](../src/cad/changes.py), line 126; [fake document](../tests/project/fake_cad.py).

3. **High — A partly completed rename revert cannot recover from a transient failure. Reproduced.** Apply a rename, then inject PermissionError when removing the renamed file during REVERT. The original has already been restored by `os.replace`; both filenames remain. After clearing the fault, retry fails with `Original rename destination now exists; refusing to overwrite it`. Status remains reverting, and overlapping changes are blocked. Recovery must recognize an already-restored, hash-verified original and resume the remaining steps. The same filesystem/database boundaries need interruption tests for ordinary restores. Source: [ChangeManager](../src/cad/changes.py), lines 169–178 and 215–230.

4. **High — Legacy write routes still lack the new backup/ChangeSet protection. Source-confirmed, pre-existing.** Sketch/P&ID approval and `/api/autocad/edit` still use legacy executors. These can partially execute, save after command errors, and—in the edit path—delete old entities before adding replacements, without calling `backup_file`. The new structured executor does use in-place assignment and backups; those guarantees do not cover the whole application. The old edit AI also still serializes up to 100 entities. The Step 7 request explicitly permitted noting this pre-existing gap, so it is remaining application work rather than evidence that the new path was never implemented. Sources: [creation executor](../src/framework/commands/executor.py), lines 380–434; [edit executor](../src/framework/commands/edit_executor.py), lines 135–204; [old AI prompt](../src/ai/edit_generator.py), lines 120–153.

5. **High — COM serialization is incomplete across workflows. Source-confirmed.** Project jobs and ChangeSet routes use the single writer/shared lock, but legacy sketch/P&ID/CAD3D writes and title-block updates do not use that mechanism. Concurrent requests can therefore mutate AutoCAD while a project operation is running. A single Uvicorn process does not serialize FastAPI's synchronous request handlers. Use one shared mutation boundary across routes, while retaining parallel offline extraction. Sources: [single writer](../src/cad/write_queue.py), [P&ID approval](../src/api/routes/pid.py), [CAD3D routes](../src/api/routes/cad3d.py), [legacy executors](../src/framework/commands/executor.py).

6. **High — Concurrent batch requests can use another request's parameters. Reproduced at the shared settings boundary.** The title-block and line-list routes temporarily overwrite module globals. Interleaving contexts A then B made A observe B's title updates; exiting A then B left A's settings installed instead of the originals. For title-block editing this can write the wrong values to drawings. Pass request parameters into the use-case functions instead of mutating module globals. Sources: [title-block settings](../src/api/routes/title_block.py), lines 15–26; [line-list settings](../src/api/routes/line_list.py), lines 16–27.

7. **Medium — Overlapping project roots make valid entity edits fail. Reproduced.** Register a parent folder and its child as separate projects, scan both, and edit a drawing in the selected child project. `_indexed_record` searches globally by path and handle, sees two records, and reports `Entity must be uniquely indexed before editing`. ChangeManager knows the selected drawing but does not pass its entity identity. Scope resolution to the selected project/drawing, and define how the other project's cached index is invalidated after a shared physical file changes. Sources: [global lookup](../src/framework/commands/modification_executor.py), lines 34–45; [caller](../src/cad/changes.py), lines 110–111.

8. **Medium — Closed drawings can remain permanently marked open. Reproduced.** `get_document` records `is_open=1`. Closing that document externally leaves the row unchanged; a filesystem rename still fails even when the fake application's open-document count is zero. Normal external close/AutoCAD exit is not reconciled; only the revert path clears these flags. Provide a reliable close/session reconciliation mechanism while retaining the filesystem-only rename path. Sources: [session tracking](../src/cad/session.py), lines 28–45; [rename guard](../src/framework/commands/modification_executor.py), lines 175–179.

9. **Medium — A valid Windows path using forward slashes breaks filesystem-only rename. Reproduced.** A rename through ChangeManager with `Path.as_posix()` fails with `AttributeError: 'NoneType' object has no attribute 'Documents'`. Target keys are canonicalized, but `rename_paths` contains raw strings. The canonical path is misclassified as requiring COM even though the rename-only session is None. Normalize operation paths once before all membership/conflict checks. Source: [ChangeManager](../src/cad/changes.py), lines 64–84.

10. **Medium — The general command schema accepts operations its executor cannot execute. Reproduced.** A sequence containing SET_LAYER_COLOR passes `validate_command_sequence` with zero errors, then `_execute_one_command` raises `Unsupported command type: SET_LAYER_COLOR`. The sibling structured executor works, but the legacy generator/approval boundary shares the expanded schema without dispatching those variants. Reject incompatible sequences before any mutation or route them deliberately through the structured workflow. Sources: [schema extension](../src/framework/commands/schema.py), line 333; [dispatch table](../src/framework/commands/executor.py), lines 294–317.

11. **Medium — P&ID/CAD3D approval tokens remain replayable. P&ID reproduced; CAD3D source-confirmed.** Approving one P&ID token twice invoked execution twice and left the token valid. Neither cache implements expiry or successful consumption. Accidental retries can create duplicate geometry. Use atomic one-time claims, expiry, and a documented retry policy. Sources: [P&ID approve](../src/api/routes/pid.py), line 91; [CAD3D approve](../src/api/routes/cad3d.py), line 414.

12. **Medium — Audit history misreports project failures and leaves validation failures unfinished. Reproduced through the actual FastAPI app.** A project execute response with `status="error"` was logged as `status="ok"`; `_status_from_result` only recognizes `ok=False`. A registration request returning HTTP 422 left a `started` row with no completion timestamp, because request validation bypasses the endpoint wrapper. Preserve the existing jobs schema, but finalize audit rows from actual HTTP/domain outcomes. Sources: [status inference](../src/api/main.py), line 112; [middleware](../src/api/main.py), lines 272–285.

13. **Medium — Durable jobs have no interrupted-run recovery. Source-confirmed.** Execution claims pending jobs as running, but there is no restart reconciliation/lease or resume path. The job-to-ChangeSet link is inserted only after `manager.apply` returns. A process interruption can leave a running job with no linked result; another execute attempt refuses it. ChangeSets may still be discoverable separately, but the job itself is stranded. Link work durably before mutation and reconcile interrupted jobs without blindly replaying operations. Source: [orchestrator](../src/cad/orchestrator.py), lines 106–125.

**Other unfinished work and limits**

- **DWG deployment:** configure/install a converter and validate real DWG → DXF → index → COM edit → re-extract → KEEP/REVERT on copies of representative files. The injectable interface is correctly present; absence of a bundled converter was explicitly allowed. It nevertheless means the default DWG workflow is not operational in this environment yet.
- **Geometry coverage:** length resize is limited to LINE; radius resize to CIRCLE/ARC. Connectivity comes from LINE endpoints and INSERT insertion points. These are appropriate initial heuristics, not a full piping topology or automatic support/dimension/constraint-update system. Spatial distances are between bounding boxes, not exact geometry. Duplicate tags within one drawing are intentionally rejected; there is no UI to choose an individual handle in that situation.
- **Live extraction:** the inspector accepts an explicit target, but a six-method COMExtractor implementation does not exist. This is a broader architecture extension, not an unmet requirement to build .NET in Steps 1–8.
- **UI review detail:** ChangeSet rows display field/before/after without the filename or entity identity. Several files with the same field change are difficult to distinguish. The plan card has paths, but restored pending ChangeSet cards should be independently reviewable. See [changesets.js](../src/api/static/changesets.js), line 28.
- **Release completeness:** `project-chat.js`, roadmap/analysis documents, and launch scripts are untracked; sketch.html and scanner.py have uncommitted changes. A clean checkout of the current committed revision will not include all observed UI behavior. Both launcher scripts still hardcode `C:\RC-Projects\autocad-ai\autocad-ai`, while this checkout is on F:. Do not confuse working-tree functionality with a reproducible delivered release.
- **Legacy maintenance:** CAD3D port aliases differ between the component classes and routing module; unify those definitions. Vessel dimensions remain front-view-only. These are outside the narrow project-index implementation but relevant to the whole application review.
- **Documentation corrections:** the old issue list overstates some current problems. `line_list_extract.get_acad()` currently raises normal connection exceptions rather than calling sys.exit; sys.exit is in its CLI path. AI-client and vessel-planner tests now exist. Also, lack of an explicit AI timeout is not proof of an infinite wait: the client inherits SDK defaults. Those old statements should not be used unchanged as current findings.

**Requirement assessment**

| Step | Assessment |
|---|---|
| 1: schema / project registry | Implemented using the existing jobs.db connection. Legacy jobs schema file remains unchanged from its original commit. Project tables initialize on first storage access. |
| 2: offline extractor | Implemented with the six-method interface, ezdxf, and injected conversion. No COM import in the extractor. Real ODA conversion remains unverified here. |
| 3: incremental scanning | Implemented: stat first, hash when necessary, skip extraction for unchanged content. Tests count zero extraction calls on unchanged scans. |
| 4: entity index | Implemented: atomic replacement and indexed tag queries; replacement/no-duplicate tests pass. Tag identity must actually exist in source data. |
| 5: relationships / spatial | Implemented for deterministic basic heuristics; RTree actually works here, fallback covered. Broader topology is not inferred. |
| 6: structured editing | All five types exist; the structured path requires explicit targets and edits in place. Its fixture definition of done passes, with type/integration gaps above. |
| 7: ChangeSet / KEEP / REVERT | Backups, summaries, tables, KEEP and exact-byte happy-path revert exist. Validation and interruption recovery need repair before treating the feature as reliable. |
| 8: targeted planning / fan-out | Fixture acceptance passes: one relevant record, one mocked AI planning call, 3 job items for 3 matching drawings out of 10, seven files byte-identical, one ChangeSet. Project UI is present in the working tree. Legacy paths are not unified with it. |
| 9: platform decision | **Provisional 9A: keep COM.** None of the demonstrated gaps calls for a platform rewrite. |

For Step 9 specifically: no implemented requirement was found for dynamic-block data beyond the COM capabilities described in the roadmap, or for a full associative constraint graph. The vessel subsystem uses numeric geometry inputs. COM write latency has not been isolated and benchmarked as a bottleneck; audit request durations cannot establish that it was never a problem. Available DXF layouts contain plain geometry, but this does not establish the semantics of the 36 native DWGs or future customer Plant/Civil projects. There is no current evidence justifying 9B or 9C.

**Suggested repair order**

First fix saved-value verification and retryable restoration; then serialize all mutation routes and eliminate request-global parameter races. Connect generated component identities and geometry types to the index. Follow with project/path/session correctness, schema dispatch, one-time approvals, audit completion, and interrupted-job recovery. Finally complete real DWG acceptance, improve per-file ChangeSet presentation, and package the untracked UI/setup work. Re-run the full suite with regression coverage for these failures. No .NET or Plant-specific engine is needed to address this list.
